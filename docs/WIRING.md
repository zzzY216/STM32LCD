# ESP32 ↔ STM32 接线指南

## 一、最简接线（3 根线）

只需要 3 根线就能通讯：

```
ESP32                     STM32F103C8
─────────────────────────────────────────
GPIO17 (TX)  ────────►   PA10 (RX)
GPIO16 (RX)  ◄────────   PA9  (TX)
GND          ─────────   GND        ← 必须共地
```

> **共地是必须的。** 两块板子如果不共地，信号没有共同参考电平，
> 串口会收到随机乱码，且极难排查。

---

## 二、完整接线（推荐）

```
                    ┌─────────────────┐
                    │   STM32F103C8   │
                    │                 │
    ┌──────────┐    │  PA9  ──────────┼──── STM32 的 TX
    │  ESP32   │    │  PA10 ──────────┼──── STM32 的 RX
    │          │    │                 │
    │  GPIO17 ─┼────┼──► PA10         │
    │  GPIO16 ◄┼────┼─── PA9          │
    │          │    │                 │
    │  GND  ───┼────┼─── GND          │
    │  3V3  ───┼────┼─── 3.3V（可选） │
    └──────────┘    │                 │
                    │  PB5  ─── SCL   │──┐
                    │  PB6  ─── SDA   │──┤
                    │  PB7  ─── RES   │──┼──► ST7789 屏幕
                    │  PB8  ─── DC    │──┤
                    │  PB9  ─── BLK   │──┘
                    └─────────────────┘
```

### 接线对照表

| ESP32 | 方向 | STM32 | 说明 |
|---|---|---|---|
| **GPIO17**（UART2 TX） | → | **PA10**（RX） | ESP32 发，STM32 收 |
| **GPIO16**（UART2 RX） | ← | **PA9**（TX） | STM32 发，ESP32 收 |
| **GND** | — | **GND** | **必须接** |
| 3V3 | — | 3.3V | 可选，见下方说明 |

> **交叉连接**：TX 接对方的 RX，RX 接对方的 TX。
> 接成 TX-TX 是最常见的错误，表现为完全收不到数据。

## 三、引脚选择说明

### 为什么用 PA9/PA10

STM32F103 的 **USART1** 默认复用就是 PA9（TX）/PA10（RX），
是外设固定映射，不用重映射配置，最省事。

### 已占用的引脚（不能碰）

| 引脚 | 用途 | 来源 |
|---|---|---|
| PB5 | 屏幕 SCL/SCLK | lcd_init.h |
| PB6 | 屏幕 SDA/MOSI | lcd_init.h |
| PB7 | 屏幕 RES | lcd_init.h |
| PB8 | 屏幕 DC | lcd_init.h |
| PB9 | 屏幕 BLK（背光） | lcd_init.h |
| **PA9** | **串口 TX（本次新增）** | uart_link.h |
| **PA10** | **串口 RX（本次新增）** | uart_link.h |

**结论：PA9/PA10 原本完全空闲，与屏幕没有任何冲突。**

### ESP32 为什么用 GPIO16/17

ESP32 的 **UART2** 默认引脚就是 GPIO16（RX）/ GPIO17（TX），
不需要额外配置。如果你已经在用 UART2，可以改到别的引脚：

```c
Serial2.begin(921600, SERIAL_8N1, 16, 17);  // RX, TX
```

## 四、供电怎么接

有三种方式，**选一种**，不要同时接：

### 方案 A：各自独立供电（推荐）

```
ESP32  ← USB 供电
STM32  ← ST-Link / USB 转串口 供电
两者 GND 相连
```

**优点**：互不干扰，调试最省心。
**注意**：GND 必须连。

### 方案 B：ESP32 给 STM32 供电

```
ESP32 3V3 ──► STM32 3.3V
ESP32 GND ──► STM32 GND
```

**优点**：只需一根 USB 线。
**注意**：
- ESP32 的 3V3 输出能力有限（约 600mA），STM32 + 屏幕大约需要 100~150mA，**够用**
- 但 ESP32 开 WiFi 时会有瞬时大电流，可能导致 STM32 复位
- 如果出现莫名复位，改用方案 A

### 方案 C：STM32 给 ESP32 供电 ❌ 不推荐

STM32F103C8 板载稳压器（如 AMS1117）通常只能提供 300~500mA，
而 ESP32 开 WiFi 时峰值可达 **500mA 以上**，会供电不足导致 ESP32 反复重启。

**除非你的 STM32 板子有独立的大电流 3.3V 输出，否则不要这样接。**

## 五、ESP32 Brownout 复位排查

接上 STM32 + 屏幕后，ESP32 可能出现**反复重启**：

```
rst:0xf (BROWNOUT_RST)
E BOD: Brownout detector was triggered
Saved PC: 0x40376998  (rtc_brownout_isr_handler)
```

典型卡点：
```
I (410) phy_init: phy_version 712,...
E BOD: Brownout detector was triggered      ← 射频启动瞬间掉电
```

### 这不是软件 bug，是供电问题

BLE 射频启动的瞬间电流从 40mA 猛增到 300~500mA。
如果电源撑不住，电压瞬间跌破阈值，芯片自我保护复位。

**注意：两个 USB 口都插电脑 ≠ 功率够用。** 原因：

| 因素 | 影响 |
|---|---|
| USB 2.0 口标称 500mA | 只是上限，前面板/经 Hub 时更低 |
| 两块板插同一个电脑 | 很可能共享同一路 5V 供电轨 |
| 线材内阻 0.5~1Ω | 500mA 时压降 0.25~0.5V |
| AMS1117 需要压差 | 输入 4.7V 时输出最多 3.6V |
| 地环路 | 两板共 GND 又各接电脑，大电流时地电位漂移 |

### 排查顺序（按有效性）

**1. 单接 ESP32 先跑通**

```powershell
# 只给 ESP32 接 USB，STM32 暂不接线
cd D:\esp32\MyProject\OLCD
.\build.ps1 -Flash -Monitor
```

看到这行才算电源够：
```
I (xxx) ble_server: advertising as "OLCD-ESP32"
```

**2. 换线换口**

- 用**粗短** USB 数据线（劣质线是头号杀手）
- 插**机箱后面**的 USB 口，优先蓝色 USB 3.0（供电更强）
- 不要经 USB Hub

**3. 分开供电（最可靠）**

```
ESP32  ← 电脑 USB（需要烧录和串口）
STM32  ← 手机充电头 / 移动电源 / ST-Link
两者只连 GND
```

**4. 加电容**

在 ESP32 的 **3V3 与 GND 之间**并：
```
100µF 电解电容 + 0.1µF 陶瓷电容
```
吸收射频启动的微秒级电流冲击，这是解决瞬态掉电最经典的手段。

### ★ brownout 档位：数字越大越宽容（不要调反）

配置项在 `sdkconfig.defaults`：

```ini
CONFIG_ESP_BROWNOUT_DET_LVL_SEL_7=y
CONFIG_ESP_BROWNOUT_DET_LVL=7
```

ESP32-S3 的档位与电压是**反的**（已在 `esp32s3/Kconfig.power` 确认）：

| 档位 | 触发电压 | 说明 |
|---|---|---|
| **7（官方默认）** | **2.44V** | 最低阈值，**最宽容** |
| 6 | 2.56V | |
| 5 | 2.67V | |
| 4 | 2.84V | |
| 3 | 2.98V | ⚠️ 更容易触发 |
| 2 | 3.19V | |
| 1 | 3.30V | 最高阈值，最敏感 |

> **踩过的坑**：曾把档位从 7 改成 3，以为"降低阈值"，
> 实际是把触发电压从 2.44V **提高**到 2.98V，
> 让 brownout 更容易发生，问题反而恶化。**不要调小。**

### 改配置后必须删 sdkconfig

`sdkconfig.defaults` 只在 `sdkconfig` **不存在**时才生效。
如果只改 defaults 而 `sdkconfig` 已存在，改动不会进入固件。

判断方法：看串口日志里的 `compile time`，如果不是你刚编译的时间，
说明烧的是旧固件。

```powershell
Remove-Item sdkconfig
.\build.ps1 -Flash
```

### 已确认无法靠软件解决的部分

ESP32-S3 上**无法在射频启动前降低发射功率**：

- `esp_bt_controller_config_t` 结构体（`esp_bt.h` 第 274-344 行）**没有功率字段**
- `BT_LE_DFT_TX_POWER_LEVEL` 这个 Kconfig 只存在于 C2/C5/C6/H2，**S3 没有**
- `esp_ble_tx_power_set()` 只能在 `nimble_port_init()` **之后**调用，
  而 `nimble_port_init()` 内部先执行 `esp_bt_controller_enable()`
  把射频打开了 —— 冲击已经发生

所以这条路走不通，必须靠硬件解决。

## 六、电平兼容性

| 项目 | ESP32 | STM32F103 | 是否兼容 |
|---|---|---|---|
| IO 电压 | 3.3V | 3.3V | ✅ 完全兼容 |
| 逻辑高电平 | ~3.3V | ~3.3V | ✅ |
| 逻辑低电平 | ~0V | ~0V | ✅ |

**两块都是 3.3V 器件，可以直接相连，不需要电平转换模块。**

> ⚠️ 千万不要用 5V 的 Arduino 或 USB-TTL 直接接 STM32 的 PA10，
> 会损坏引脚。如果你手头只有 5V 的 USB 转串口调试，
> 需要加电平转换或串联分压电阻。

## 七、调试建议

### 第一步：先只接 TX/RX/GND，不接供电

用方案 A 各自供电，先确保通讯能通，再考虑合并供电。

### 第二步：用串口助手验证 STM32 能收

STM32 烧录固件后，把 **ESP32 那端换成 USB-TTL 接电脑**，
用串口助手（波特率 921600，8N1，十六进制发送）发一帧心跳：

```
A5 5A 01 00 00 00 74 F2
```

各字节含义：
```
A5 5A        帧头
01           CMD = PING
00           SEQ = 0
00 00        LEN = 0
74 F2        CRC16 = 0xF274（小端，低字节 0x74 先发）
```

**如果收到 STM32 回的 ACK**，说明固件和接线都正常。

ACK 的样子应该是（共 11 字节）：
```
A5 5A 7E 00 03 00 00 01 00 XX XX
      │  │  │  │  │  │  │  └──┴── CRC16（随内容变化）
      │  │  │  │  │  └──┴──────── 原 SEQ = 0
      │  │  │  │  └────────────── 原命令 = 0x01 (PING)
      │  │  │  └───────────────── 错误码 = 0x00（成功）
      │  │  └──────────────────── LEN = 3
      │  └─────────────────────── SEQ
      └────────────────────────── CMD = 0x7E (ACK)
```

> 具体 CRC 两字节会随内容变化，只要前 9 个字节匹配就说明应答正确。

**完整示例**：发 `A5 5A 01 00 00 00 74 F2` 后，
STM32 应当回 `A5 5A 7E 00 03 00 00 01 00 C4 9A`。

这个值已用与 STM32 端完全相同的算法验算过，可以直接用来对照。

### 第三步：接上 ESP32 联调

用 ESP32 的 Arduino 串口监视器（115200 看日志，UART2 走 921600 通讯）。

## 八、常见问题

### 收不到任何数据

按这个顺序查：

1. **TX/RX 是不是接反了？** 交叉连接：ESP32 TX → STM32 RX
2. **GND 接了吗？** 不共地是最常见原因
3. **波特率一致吗？** 两边都必须是 921600
4. **PA9/PA10 有没有被别的东西占用？** 检查有没有接其他模块
5. 用万用表量 PA10 在 ESP32 发数据时电压是否跳动

### 收到乱码

- **波特率不匹配**（最常见）
- **晶振频率不对**：确认 STM32 用的是 8MHz 晶振，且 `system_stm32f10x.c` 里配置为 72MHz
- 921600 太高，线太长导致信号失真 → 降到 460800 或 115200

**怎么改波特率**：

```c
// User/main.c
app_link_init(921600);   // 改成 460800 或 115200
```

ESP32 端也要同步改：

```c
Serial2.begin(460800, SERIAL_8N1, 16, 17);
```

### 能收到但 CRC 一直错

- 检查 ESP32 端 CRC 算法是否与协议文档一致
- 验证基准值：`crc16("123456789", 9)` 必须等于 `0x29B1`
- 检查字节序：CRC 是**小端**（低字节先发）

### 传图传到一半就停

- **接收缓冲溢出**：STM32 是软件 SPI 写屏，速度有限
- 解决办法：ESP32 每发 512 字节后加 `delay(2)`
- 或减小每片大小到 256 字节

### 屏幕闪烁 / 背光抖动

- 如果用了 `LCD_SetBrightness()` 且值在 1~99 之间，是软件 PWM 导致的
- 调成 0 或 100 可消除（这两档是直接给电平，不走 PWM）
